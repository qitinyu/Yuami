Yuami 本地编辑指南

本文档详细介绍如何在本地拉取、配置、编辑和部署 Yuami 个人博客。涵盖从环境搭建到各版块内容编辑的完整流程，帮助你轻松管理博客的每一个细节。

概述

Yuami 是一个基于 Astro v5 框架的二次元风格个人博客，使用 Content Collections API 管理 Markdown 内容，数据与视图分离——各版块内容存放在独立的 .ts 数据文件中，页面组件只负责渲染，修改数据无需改动页面代码。博客内置了 Twikoo 评论系统、Umami 数据统计、Live2D 看板娘、网易云音乐播放器、樱花飘落特效等功能。

技术栈速览： Astro 5 · TypeScript · CSS Variables（明暗主题） · Content Collections · Twikoo 1.7.9 · PixiJS + Cubism 4 · Meting API

拉取仓库

Yuami 博客的源码托管在 GitHub，通过以下命令将仓库克隆到本地：

bash 
git clone https://github.com/qitinyu/Yuami.git
cd Yuami

克隆完成后，你将获得完整的项目源码，但不包含 node_modules（依赖目录）和 public/live2/models/ 下的 Live2D 模型文件（模型文件较大，需单独下载放入）。

配置环境

安装 Node.js

Yuami 需要 Node.js 18+ 环境。推荐使用 LTS 版本，可前往 Node.js 官网 下载安装，或使用 nvm 管理版本：

bash 
node -v   # 确认版本 ≥ v18.x
npm -v    # 确认 npm 可用

安装项目依赖

bash 
npm install

依赖安装完成后，项目根目录下会生成 node_modules/ 文件夹和 package-lock.json。

放置 Live2D 模型（可选）

Live2D 看板娘需要 moc3 格式的模型文件。将模型文件夹放入对应目录：

目录结构 
public/live2/models/
├── wwa/                    ← 模型文件夹名与 config.ts 中 modelName 对应
│   ├── wwa.model3.json     ← 模型配置（必需）
│   ├── wwa.moc3            ← 模型数据（必需）
│   ├── wwa.physics3.json   ← 物理参数
│   └── wwa/                ← 贴图目录
│       └── texture_00.png
├── cmtt/
│   ├── cmtt.model3.json
│   └── ...
└── jk/
    ├── jk.model3.json
    └── ...
注意：模型文件较大，未纳入 Git 仓库管理。你需要自行下载 moc3 模型并放入 public/live2/models/ 目录。文件夹名需与 config.ts 中 live2d.modelList 的 name 字段一致。

放置字体文件（可选）

博客默认使用「朱雀仿宋」字体，需将字体文件放入 public/font/zqfs.woff2。如果未放入，浏览器会自动回退到 Noto Sans SC。

开发与构建

启动本地开发服务器

bash 
npm run dev

浏览器访问 http://localhost:4321 即可实时预览。修改文件后页面会自动热更新。

构建生产版本

bash 
npm run build

构建产物在 dist/ 目录下，可直接部署到任何静态托管平台。

本地预览构建结果

bash 
npm run preview

关于 Yuami

Yuami 是一个以二次元美学为设计灵感的个人博客系统。名字取自日语「湯あみ」（入浴），寓意在信息的洪流中寻得一方清净之地。博客整体采用紫蓝色调（#7D98F5）为主题色，配合毛玻璃效果、樱花飘落特效和 Live2D 看板娘，营造出沉浸式的二次元氛围。

核心特性

  • 明暗双主题 — CSS Variables 驱动，一键切换，全局联动
  • Content Collections — Astro 原生 Markdown 内容管理，博文/旅记独立目录
  • 数据与视图分离 — 番剧、游戏、LES、友链等数据存放在独立 .ts 文件中，修改内容无需动页面代码
  • Twikoo 评论 — 通用组件化集成，所有页面统一引用，CDN 双源回退加载
  • Umami 统计 — 隐私友好的访问统计，条件渲染，本地开发不计数
  • Live2D 看板娘 — PixiJS + Cubism 4 SDK，支持拖动、多模型切换、隐藏/恢复
  • 音乐播放器 — 第三方 Meting API 代理，支持网易云/QQ音乐歌单
  • 客户端分页 — 列表页内置分页 + 筛选联动，无需后端支持
  • 全站响应式 — 从桌面到手机的自适应布局

全局配置（config.ts）

config.ts 是博客的核心配置文件，几乎所有站点信息都在这里集中管理。下面逐一说明各配置项的用途和修改方式。

站点基本信息

typescript 
export const siteConfig = {
  title: 'Yuami',                              // 站点名称
  subtitle: '生命绚烂，别被黑暗压垮',            // 副标题/格言
  description: 'Yuami的个人博客 - 记录生活、思考与创造',
  url: 'https://yqamm.cc.cd',                 // 站点URL
  author: 'Yuami',                             // 作者名
  email: '484894496@qq.com',                   // 邮箱
  themeColor: '#7D98F5',                       // 主题色（同步修改 global.css 中的 CSS 变量）
};

音乐播放器

typescript 
music: {
  api: 'https://api.qijieya.cn/meting/',   // Meting API 代理地址
  server: 'netease',       // 平台：netease / tencent / kugou
  type: 'playlist',        // 类型：playlist / song

更换歌单：打开网易云音乐网页版，找到目标歌单，复制 URL 中的 ID（如 playlist?id=123456789 中的 123456789），替换 id 字段即可。

Twikoo 评论

typescript 
twikoo: {
  envId: 'https://twikoo-nt.netlify.app/.netlify/functions/twikoo',
  region: 'gansu',     // 腾讯云部署时填写区域，如 ap-shanghai
},

Twikoo 已通过通用组件 src/components/Twikoo.astro 集成到所有页面。只需填写 envId 即可启用。如果 envId 为空，评论区会显示配置提示。CDN 加载采用 jsDelivr 主源 + npmmirror 回退策略。

Umami 统计

typescript 
umami: {
  src: 'https://cloud.umami.is/script.js',       // 脚本地址（非分享链接）
  websiteId: '8fc5914d-67a8-4f9b-937d-a9c58df46d4a',  // 网站 ID
},
Umami 通过域名过滤统计数据，本地开发（localhost）访问不会被计数，这是正常行为。src 应填写 Umami 后台的脚本地址，不是浏览器分享链接。

Live2D 看板娘

typescript 
live2d: {

  modelPath: '/live2/models/',
  modelName: 'wwa',           // 默认模型名
  position: 'left',           // 位置：left / right

首页 · 尺素

首页由左侧边栏和右侧主内容区组成，编辑文件为 src/pages/index.astro。

左侧边栏

边栏的三个板块数据均来自 config.ts：

  • 个人信息 — 头像（public/avatar.webp）、名称、格言、社交链接，均读取自 siteConfig
  • 站点公告 — 读取自 siteConfig.siteAnnouncements
  • 站点统计 — 读取自 siteConfig.siteStats，运行天数由 JS 自动计算
修改头像只需替换 public/avatar.webp 文件即可，建议 200x200px 以内的 WebP 格式。

右侧内容区

  • 青衿（打字机效果） — 编辑 index.astro 底部 <script> 中的 texts 数组
  • 悟我（关于我） — 直接编辑 index.astro 中 home-section 的 HTML 内容
  • 项目展示 — 数据来自 config.ts 的 projects 数组

博文

博文使用 Astro 的 Content Collections 管理，内容由 Markdown 文件驱动，无需手动编辑页面代码。

添加新博文

  1. 在 src/content/posts/ 目录下创建新的 .md 文件，文件名即为 URL 中的 slug（如 my-new-post.md → 访问路径 /blog/my-new-post）
  2. 在文件顶部添加 frontmatter：
markdown 
---
title: '我的新文章'
date: '2026-05-22'
tags: ['技术', '随笔']
excerpt: '这是文章的简短摘要，会显示在列表卡片中。'
cover: '/images/blog/my-post-cover.webp'   # 可选
---

# 文章标题

这里写正文内容，支持完整的 Markdown 语法……

## 二级标题

正文段落……

### 三级标题

更多内容……

Frontmatter 字段说明

字段类型必填说明
titlestring是文章标题
datestring是发布日期，格式 YYYY-MM-DD
tagsstring[]是标签数组
excerptstring否摘要，显示在列表卡片中
coverstring否封面图片路径

删除/修改博文

直接删除或编辑 src/content/posts/ 下对应的 .md 文件即可。列表页和详情页均通过 Content Collections API 自动生成，无需手动同步。

博文列表页按日期倒序排列，支持标签筛选和客户端分页（每页6篇）。修改每页数量：编辑 src/pages/blog/index.astro 中的 ITEMS_PER_PAGE 常量。

旅记

旅记的编辑方式与博文完全一致，只是文件位于 src/content/diary/ 目录，访问路径为 /travel/{slug}。

tags: ['旅记', '春天']

春天的风吹过原野，我踏上了久违的旅途……

番剧

番剧数据存放在 src/data/bangumi.ts，与页面完全解耦，修改数据文件即可自动更新。

数据结构

typescript 
// src/data/bangumi.ts
export const bangumiList = [
  {
    title: '葬送的芙莉莲',         // 名称
    cover: '/fanju/frieren.webp',  // 封面图路径（对应 public/fanju/ 目录）
    score: 10,                     // 评分 0-10
    status: '看过',                // 状态：'看过' / '在看' / '想看'
    comment: '史诗级的冒险与告别',  // 短评
    url: 'https://bgm.tv/subject/399456',  // 外部链接（可选，留空则不可点击）
  },
  // 继续添加……
];

操作步骤

  1. 将封面图片放入 public/fanju/ 目录（推荐 WebP 格式，800x450px）
  2. 打开 src/data/bangumi.ts，在 bangumiList 数组末尾添加新条目
  3. 保存文件，开发服务器自动热更新

回忆（相册）

相册数据存放在 src/data/memory.ts，照片文件存放在 public/huiyi/ 目录下按相册 ID 组织的子文件夹中。

typescript 
// src/data/memory.ts
export const albumList = [
  {
    id: 'spring-2026',              // 相册ID，同时对应 public/huiyi/ 下的目录名
    title: '2026 春日随拍',          // 相册标题
    desc: '春天来了，万物复苏……',     // 相册描述
    cover: '/huiyi/spring-2026/cover.webp',  // 封面图
    count: 12,                       // 照片数量
  },
];

添加新相册

  1. 在 public/huiyi/ 下创建与 id 同名的子目录（如 public/huiyi/summer-trip/）
  2. 将照片放入该目录，推荐 WebP 格式，命名如 01.webp、02.webp……
  3. 在 src/data/memory.ts 的 albumList 数组中添加新条目
  4. 更新 count 为实际照片数量

常见问题

Q1：修改后页面没有变化？

确保本地开发服务器正在运行（npm run dev），且浏览器没有缓存。尝试硬刷新（Ctrl + Shift + R）。

Q2：构建报错？

检查 Markdown 文件的 frontmatter 格式是否正确，HTML 标签是否闭合。运行 npm run build 查看详细错误信息。

Q3：看板娘不显示？

  1. 检查 config.ts 中 live2d.enabled 是否为 true
  2. 检查 public/live2/models/ 目录下是否有完整的模型文件
  3. 检查浏览器控制台是否有加载错误
  4. 移动端默认关闭看板娘（mobileOff: true），请用桌面浏览器测试

Q4：评论区显示「Twikoo 评论系统待配置」？

说明 config.ts 中的 twikoo.envId 为空。需要部署 Twikoo 后端（支持 Vercel/Netlify 云函数等），获取环境 ID 后填入即可。

Q5：Umami 统计本地不显示数据？

这是正常行为。Umami 通过域名过滤统计数据，localhost 访问不会被计数。部署到线上域名后即可正常统计。

Q6：音乐播放器无法播放？

  1. 检查 Meting API 是否可访问（https://api.qijieya.cn/meting/）
  2. 检查歌单 ID 是否正确
  3. 部分歌曲可能因版权限制无法播放（网易云版权问题）

Q7：如何添加新页面？

  1. 在 src/pages/ 下创建新的 .astro 文件
  2. 在 config.ts 的 navItems 中添加导航项
  3. 页面模板参考现有页面结构，引入 BaseLayout 和 SidebarWidget

Q8：字体没有生效？

确认 public/font/zqfs.woff2 文件存在。字体文件较大（约2.5MB），首次加载可能需要时间。检查浏览器控制台 Network 面板确认字体是否加载成功。
